# Report analyses (not part of `make all`)

Two one-off validation studies of the gate-level method (Part B) whose results the report quotes.
They need ngspice and minutes of simulation, so they are not pipeline steps. `make_numbers.py`
reads only the small CSVs here, and it marks every macro taken from them as
`\todo{stale: ...}` when the gate results they were computed against no longer match
`results/tables/gate_results.csv`. Rerun both studies after any change to the models or gate code.

All commands run from the repo root and write only inside `report/analysis/`.

## SPICE oracle (`oracle.py`, `oracle_sub.py` → `oracle/`)

Each transistor of each (gate, inputs, corner) is simulated **alone** in ngspice at exactly the
feature row the ML model sees (in-gate terminal voltages, snapped gate voltage). That gives the true
current of every model input. Composing those SPICE currents with the same KCL code as step 08 must
reproduce the gate's own SPICE leakage, and replacing one (case, current) group of ML outputs by
the SPICE values shows how much of the gate error that group causes.

```bash
uv run python report/analysis/oracle.py     report/analysis/oracle   # reuses oracle/oracle_spice.csv
uv run python report/analysis/oracle_sub.py report/analysis/oracle
```

| File | Content |
|---|---|
| `oracle/oracle_spice.csv` | per-FET SPICE currents (cache; delete it to re-simulate, 16,800 decks) |
| `oracle/oracle_summary.csv` | gate `i_vdd` error with ML currents vs with per-FET SPICE currents |
| `oracle/error_sources.csv` | gate accuracy if one (case, current) group were exact |
| `oracle/worst_case_attribution.csv` | the same, per worst gate case (NAND2 10, NOR2 10, NOR2 11) |

## Fresh-corner check (`fresh_corners.py`, `compare.py` → `fresh_corners/`)

200 **new** PVT corners (seed `seeds.corners + 1000`, same distributions as step 06) are run
through the step-07 SPICE reference and the step-08 ML, and summarised like step 09. The original
corners were used to diagnose the data sampling; this checks that nothing was tuned to them.

```bash
uv run python report/analysis/fresh_corners.py report/analysis/fresh_corners   # ~3,600 ngspice decks
cp data/gates/gate_results.csv      report/analysis/fresh_corners/gate_results_orig.csv
cp results/tables/gate_results.csv  report/analysis/fresh_corners/gate_results_table_orig.csv
uv run python report/analysis/compare.py report/analysis/fresh_corners
```

Only the summaries and the SPICE inputs (`corners_fresh.csv`, `gate_spice_fresh.csv`) are committed;
`gate_results_orig.csv`, `gate_results_fresh.csv` and `gate_ml_fresh.csv` are regenerated by the
commands above.
