# 5. Test-circuit results  <!-- owner: P4 Gopal -->
- Circuit gate-level structure: `parity8` is a balanced XOR tree (4 + 2 + 1 = 7 XOR2), each XOR2
  built from 4 NAND2, i.e. **28 NAND2** and no other gate type. Output `parity` = XOR of the 8 bits
  (1 for an odd number of ones). 256 input vectors × 200 shared corners = 51,200 transistor-level
  SPICE decks (`netlists/examples/circuit_parity8.sp` is the corner-0, all-zeros deck).
  (If the circuit is switched to `cla3`: 42 gates = 24 NAND2 + 12 AND2 + 6 OR2, 128 vectors.)
- Method: SPICE reference = one flat deck per (vector, corner) built from the Part B gate subckts
  (same sizing, same corners, one `.model` draw per device type per corner). ML estimate = logic
  simulation gives each gate's input bits, then the sum of the Part B gate-ML leakages
  (`GateLeakageModel`). Primary inputs sit exactly at 0/VDD and inter-gate loading is ignored.
- Verification: the logic simulation equals the behavioural reference on all 256 vectors
  (`tests/test_circuit.py`), and every SPICE deck's output level is checked (`logic_ok`).
- Circuit results table (`results/tables/circuit_results.md`) vs gate-level accuracy
- Circuit parity plot (`results/plots/circuit_parity.png`)

# 6. Error analysis  <!-- owners: P2 Joanna (transistor), P3 Sindhuja (gate), P4 Gopal (circuit) -->
- Where the largest errors occur: case, gate, input combination, corner conditions (high T, low vth0, ...)
- Explanation: model extrapolation, vg snapping at n1, inter-gate loading, near-zero currents, ...
- Circuit (P4): `results/tables/circuit_error_drivers.md` ranks what the signed circuit error
  correlates with. Inter-gate loading: a gate input that is high draws gate-tunnelling current
  through its driver from VDD. A gate bench with an ideal input source does not count it, so the
  hierarchical sum under-estimates. On the dev fixture card, adding the downstream gate-input
  currents back (the "loading-corrected (diagnostic only)" row of the circuit table, which uses
  SPICE input currents and is not a prediction) reduced the error of a SPICE-exact gate table from
  54 % to 0.4 %, so the composition itself is exact and loading is the error source. Redo this
  with the final gate table and quote the assigned-card numbers.
